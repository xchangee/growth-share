# Contributing

Thanks for helping improve Open Creative Wall. Keep contributions narrow, reproducible and safe to publish.

## Before changing code

1. Read `AGENTS.md` and the relevant guide under `docs/`.
2. Install exactly the locked JavaScript dependencies with `npm ci`.
3. Inspect existing working-tree changes and do not overwrite unrelated work.
4. For visual changes, start the app and capture the current rendered state before editing.

## Privacy and content rules

This public template accepts synthetic profile data only.

- Never commit employee IDs, roster-derived names or tenure, emails, phone numbers, personal photos, private source paths or assets derived from real people.
- Do not paste production datasets into issues, fixtures, screenshots or generated files.
- Display names must remain randomly composed and unrelated to known identities.
- Do not add company names, logos, trademarks, internal event copy or licensed music without a cleared entry in `ASSET-PROVENANCE.md`.
- Keep `profile-*` IDs, the generated profile module, 674 portrait SVGs and the avatar atlas in sync through the generators.

A contribution that cannot demonstrate safe provenance will be declined even if it works technically.

## Development workflow

Use `src/config/site.ts` for ordinary title, copy, mode-label, word-sequence and music configuration changes. Read `docs/CUSTOMIZATION.md` before changing component internals.

Generated data must be changed through the documented commands:

```bash
npm run generate:profiles -- --seed <public-demo-seed>
npm run generate:avatars
```

Do not hand-edit `src/data/syntheticProfiles.generated.ts`, `src/assets/synthetic-avatars/profile-*.svg`, `public/assets/avatar-atlas.png` or `scripts/avatar-output.manifest.json`. The avatar command replaces generated outputs and their manifest after validation, so run it only when the four authorized source sheets are intentionally changing.

The neutral pattern, coordinate map, paper grain, memory symbol and favicon are generated by `npm run generate:textures`. Do not hand-edit those SVGs or `scripts/demo-textures.manifest.json`; change the generator and keep the Lucide notices instead.

## Validation

Before requesting review, run:

```bash
npm run verify
```

Visual or interaction changes also require real-browser verification of:

- 01/02/03 switching and Q/W/E shortcuts;
- the configured letter sequence and profile rotation;
- music enabled and disabled states, if touched;
- normal WebGL and reduced-motion/fallback presentation;
- browser console errors, missing assets and target viewport geometry.

Report the viewport, browser, commands and results in the change description. If a generator ran, include its reported hashes and confirm that the expected file counts stayed in sync.

## Change scope

- Preserve `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs` and `tests/sites-worker.test.mjs` as one tested Sites integration unless the contribution explicitly updates the integration and its tests.
- Treat changes to profile count, atlas rows/columns, rendering budget and source-sheet grid as coordinated architecture changes rather than one-line configuration edits.
- Do not add generated `dist/`, `node_modules/`, secrets, editor state or local absolute paths.
- Update README, architecture, customization and provenance documentation when behavior or assets change.

## Reporting problems

Use ordinary issues for reproducible public bugs and feature proposals that contain no sensitive data. Use the private process in `SECURITY.md` for vulnerabilities, leaked credentials, real-person data or confidential material.
